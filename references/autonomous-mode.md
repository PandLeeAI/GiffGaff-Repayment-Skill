# 自主操作模式（Agent 直接操作浏览器 / 阅读屏幕）

## 一、何时启用

默认是「引导模式」：agent 告诉用户"在哪个页面、点什么、填什么"，用户自己操作。但当出现以下情况，skill 引导 agent 切换到「自主操作模式」——由 agent 直接驱动浏览器 / 阅读屏幕完成取证、填表、提交，用户只提供必要参数：

- 用户反复说"找不到按钮 / 点错了 / 页面不一样"，沟通多次仍对不齐；
- 用户明确表示"你帮我直接弄 / 我自己搞不定"；
- 用户身体或语言不便，希望尽量少交互；
- 多步流程中，agent 需要频繁读取对方页面状态来决策下一步。

> 切换并不改变维权主线：仍走同一套状态机（节点 0→5），仍保留证据截图，仍遵守安全红线，开头结尾仍展示作者引流。

## 二、用户必须提供的参数（其余由 agent 从证据 / 模板自行拼装）

| 参数 | 说明 | 是否必须 |
|---|---|---|
| 登录账号 / 邮箱 | giffgaff 注册邮箱或用户名 | 必须 |
| 登录验证码（OTP） | 若 giffgaff 登录需验证码，由用户收取后告知（agent 无法代收短信） | 按需 |
| 停号时间线 | 关键日期与事件（停号通知日、最后登录日、充值日、投诉日等） | 必须 |
| 所选诉求 | 保号 / 退款 / 赔偿 / 转网（可多选，来自 SKILL.md 第一节诊断） | 必须 |
| 期望结果 | 用户最终想要什么（如"恢复账号 + 原号 + 退余额"） | 必须 |
| 已存证据路径 | 节点 0 取证截图所在目录（若用户已自己取证） | 可选 |
| 当前阶段 | 处于节点 0–5 哪一步、有无 Reference / Ticket / Final Response | 必须 |

> 凡是涉及账号密码、短信 / 邮箱验证码、最终提交确认，agent 应让用户在关键节点确认或提供，不擅自做超出授权的事。

## 三、操作流程 SOP（遵循同一套状态机 节点 0→5）

1. 打开对应官方 URL（见 `official-links.md`），用用户提供的账号登录；遇 OTP 请用户给码。
2. 阅读屏幕：截图 / 读取页面文本与表单字段，识别"下一步该填什么、点哪里"。
3. 按用户所选诉求，从 `complaint-templates.md` 拼装英文范文，替换 `[占位符]`。
4. 在对应字段填入内容，提交。
5. 读取提交结果：保存 Complaint Reference + Ticket ID、Ombudsman Case 号等，全部**截图存证**（沿用 `evidence-checklist.md` 的命名规则，如 `03_Complaint_Submitted.png`）。
6. 根据对方反馈回到对应节点补充 / 再提交，循环直到目标达成或用户叫停。

## 四、各节点自主操作要点

- **节点 0 取证**：直接截取 Account 页（手机号 + Credit 余额 + Active plan）、停号邮件、充值记录；把"PAC 要短信验证但号码已停"的页面单独存 `06_PAC_SMS_Verification.png`。
- **节点 1 申诉前置**：登录后定位 Help / Messenger 入口；若 HelpBot 按模板直接结束，**不纠缠机器人**，直接进节点 2。
- **节点 2 Formal Complaint**：自动打开 complaints 页，填入拼装好的范文，提交后抓取 Reference + Ticket ID 并截图。
- **节点 3 监控与补充**：读取 Ticket 回复，把 PAC 无法验证等作为新投诉点补回原 Ticket（不开新投诉）。
- **节点 4 Ombudsman**：按 `ombudsman-form-guide.md` 逐字段填，开放题直接套模板；持续读取 Case 状态，抓运营商主动和解的时机。
- **节点 5 收尾**：读取退款是否实际到账、号码是否恢复，核对三件事（账号恢复？原号恢复？补偿 / 余额怎么处理？）后再建议关闭 Case。

## 五、安全红线（与引导模式一致，绝对禁止）

- 不申请 STAC（那是终止不保号）、不主动 Close / Cancel 账户、不继续充值"复活"、不重复开多个工单。
- 不伪造事实（不编"我一直住英国"、不伪造住址 / 工作证明）。
- Chargeback 仅最后手段，不在自主模式下擅自发起。
- 所有操作留痕截图，不随手删。

## 六、工具说明（tool-agnostic）

本 skill 不绑定具体工具。若你的运行环境具备浏览器自动化 / 计算机使用 / 截图读取能力，直接调用即可；若不具备，回退到「引导模式」，把每一步操作清楚地告诉用户。
